Challenges

PPI-PhysioClassification — Discrimination of physiological vs. non-physiological (crystallographic) homodimer interfaces

Implementing the PPI Benchmark as an OpenEBench Experiment

ELIXIR 3D-BioInfo Community · PPI-PhysioClassification challenge · overview
This page implements the physiological-vs-crystallographic protein-protein interface classification benchmark (Schweke et al.) as an OpenEBench-style Benchmarking Event, following the OpenEBench Scientific Benchmarking Data Model (community → benchmarking event → challenge → participants → metrics). It is a working preview, not a connection to the live openebench.bsc.es service.

The challenge

1671 homodimer entries (840 physiological, 831 non-physiological/crystallographic, after curation) are scored and ranked by 14 participant methods — DeepRank-GNN, Rosetta InterfaceAnalyzer, Voronota, DLScore-BC, IES normalized, NIPacking, QSQE, ISPRED4, GOAP, MaSIF, CP/COCOMAPS, shape_hydro_tails, ScanNet ProbaConsensus, and a cross-group Random Forest consensus — each evaluated on 5 metrics (AUROC, AUCPR, Balanced Accuracy, F1, MCC).

Leakage-safe cross-validation

Because many entries share homologous chains, metrics computed by simple resubstitution over-estimate real-world performance. This package instead provides 4 homology-aware CV splitting strategies (CATH/UniProt-based, this package's own MMseqs2 clustering, an authoritative blastclust reference, and a recommended combined union of the two), documented in CV_SPLITTING_STRATEGIES.md, so every participant's decision threshold is learned only from the other folds, never from the held-out one.

What's on this page

Results — the real OpenEBench Scientific Visualizer renders the AUC-ROC-vs-Accuracy leaderboard chart plus a full metrics table and a quartile/cluster ranking view. Datasets and Tools link to the underlying data files and participant tool registrations. Submit new predictions runs the exact same leakage-safe cross-validation engine (ported to JavaScript and numerically validated against the original Python implementation) entirely in your browser — no backend, nothing uploaded anywhere — to evaluate and rank your own scores against the 14 baselines.

OEB Bundle — submitting this benchmark to OpenEBench

The OEB Bundle link in the sidebar downloads oeb_ppi_benchmark-v1.1.0.zip, release 1.1.0 of the package (release page on GitHub), the complete, self-contained OpenEBench submission package behind this page: the Community/Benchmarking Event/Challenge/Dataset metadata JSON files (OpenEBench Scientific Benchmarking Data Model), the submission files of the 14 reference methods (13 research groups and a cross-group random-forest consensus), the offline copy of the OpenEBench JSON Schemas used to validate them, the workflow scripts, draft Docker files for each workflow step, and an installation guide (INSTALL_OPENEBENCH.md). The interactive evaluation is this page.
To actually import this data into OpenEBench after downloading:
  1. Extract the zip, then run cd oeb_ppi_benchmark && python3 workflow/prepare_for_openebench_submission.py. The wizard replaces the placeholder Community ID and contact emails throughout every metadata file with your real ones, and re-validates each file against the bundled OpenEBench JSON Schemas (schemas/) as it goes.
  2. Build and push the three Docker images under workflow/ (Dockerfile.validate, Dockerfile.compute_metrics, Dockerfile.consolidate) to a registry OpenEBench's VRE can pull from -- every benchmarking workflow step on OpenEBench's infrastructure runs as a container for reproducibility.
  3. Register the participant tools and this benchmarking workflow with OpenEBench (or your ELIXIR community's OpenEBench liaison), providing the Community ID, the Git repository URL/tag, and the Docker image references from the previous two steps -- the wizard drafts a ready-to-send support-request email summarizing these for you.
  4. Once OpenEBench ingests the metadata and runs the workflow, this benchmark becomes a real, citable Benchmarking Event on openebench.bsc.es, and anyone can submit new predictions there the same way this page's own Submit new predictions tab demonstrates locally.
Full detail on what remains to be filled in (real Community ID, registered Tool IDs, contact persons and e-mails, built images) is in INSTALL_OPENEBENCH.md and OPENEBENCH_SUBMISSION_READINESS.md inside the bundle.

Submit new predictions

Upload a scoring-function predictions file and see how it ranks against the 14 package participants, under a declared, leakage-safe cross-validation splitting procedure -- computed entirely in your browser (the file is never uploaded anywhere).
Two evaluation modes are available. Cross-validation (default, for scores that have no declared threshold): for each fold of the chosen splitting strategy, the decision threshold used by Balanced Accuracy / F1 / MCC is learned only from the other folds (Youden's J statistic), never from the held-out fold, and the reference methods are shown evaluated in the same way. Predefined threshold (for predictions with a threshold fixed beforehand, or binary 0/1 predictions): nothing is learned, the metrics are computed once on all entries covered, and the reference methods are shown at their published thresholds. A predefined threshold that was tuned on this benchmark is as optimistic as those published thresholds. All computation happens client-side in JavaScript -- your file is read locally via the browser's File API and never leaves your machine.
full description of all 4 strategies ↗
Predefined threshold: you must enter the threshold of your submission, on the scale of your scores (entries with a score ≥ the threshold are predicted physiological). The only exception is a file of binary predictions (0/1, True/False, biological/crystal), which has no threshold and is evaluated as it is. AUROC and AUCPR of a binary file describe its single operating point.
Columns: entry_id (e.g. 1a17_6) and a score column named score, raw_score or raw_score_oriented -- higher value must mean MORE physiological. download a template ↓ or try the bundled demo file.
